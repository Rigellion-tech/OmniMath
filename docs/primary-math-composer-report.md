# Primary math composer redesign report

1. Existing primary architecture: `Home` owns the session shell and header; `ProblemInput` owned the primary typed problem draft/history/solve submission, with OCR and `ImageUpload` as sibling entry paths. Follow-up and pinned explanation inputs remain in their existing secondary components.
2. Reused infrastructure: the registry/catalog remains the source for 461 symbols/operators/notation entries and 62 structures, with aliases, categories, insertion metadata, and recent-symbol support.
3. Editor approaches considered: KaTeX is display-only; MathQuill was considered but would require more adapter and integration work; a custom contenteditable engine was rejected for cursor, placeholder, matrix, and nested-expression risk.
4. Selected editor: MathLive 0.110.0, MIT licensed and pinned, supplies structured editing, nested placeholders, keyboard navigation, editable arrays, and deterministic LaTeX. A small React web-component bridge owns its lifecycle. Fonts/CSS are local; CDN font loading, sounds, and the optional compute engine are disabled. Its parser/serialization behavior and bundle size remain dependency maintenance considerations. KaTeX output and solved-expression semantic rendering remain separate.
5. Component boundary: `PrimaryMathComposer` and `VisualMathField` own visual math editing; the old `ProblemInput.jsx` is a compatibility export. `Home` supplies session ownership and existing solve callbacks. The session-keyed editor sits beside a stable image-upload component so switching the editor does not unmount an in-flight OCR workflow. Secondary inputs do not import the primary editing subsystem; this is a component boundary, not CSS hiding.
6. Follow-up isolation: hover/semantic ownership, pinned-window provenance, backend routes, and lifecycle remain untouched; the real-browser pinned provenance regression passed, and secondary-input architecture coverage is included in serialization tests.

## Cursor-position investigation and final evidence

The last test was reviewed rather than accepted as a test-only failure by assumption. Inspection of the installed MathLive 0.110.0 implementation shows fraction insertion with `selectionMode: "placeholder"` selects the numerator. Its keyboard sink receives focus asynchronously (the library schedules it after 60ms); calling `focus()` is not itself evidence that subsequent synthetic keyboard events will reach the editor. The library's automatic editable-prompt advancement applies to read-only prompt fields, not this ordinary editable field.

A focused instrumented browser run observed the selected numerator at position 2 both before and after an empty Solve rejection. Typing `1` produced `\frac{1}{\placeholder{}}`; a second rejected Solve preserved that caret. Tab selected the denominator at position 4, and typing `2` produced `\frac12`. No production selection-reset or integration defect was reproduced in this flow. The retained older failure trace concerns an earlier empty-slot guard failure, not the later cursor-position assertion; it cannot independently establish the exact event sequence of the interrupted cursor failure.

The final test therefore removes the source-assignment workaround and tests the intended behavior more strictly: wait for actual field focus; assert numerator selection; assert both rejected submissions make zero requests and preserve selection; use real typing and Tab to fill the fraction; assert the exact canonical request and successful collapse. Production code and validation were not changed in this finishing pass. This resolves the brittle unsynchronized cursor assumption without replacing keyboard editing with `setValue()`.

Final focused cursor result: **3/3 consecutive runs passed**, with the exact same production implementation. Focused test-file lint passed (exit 0). Logs: `test-artifacts/primary-composer-final/cursor-investigation.log` and `cursor-confirmation.log`.

Evidence reconciliation: the older OCR batch has two passes plus one cold-start timeout; `session-confirmation.log` records the isolated pass for that third case. All three remain verified. The first three scope cases and the 14 other editor cases retain their established passing evidence; the two added scope cases have a passing `scope-extra-results/.last-run.json`. Broad offline results remain **1,137 total: 1,115 passed, 21 skipped, 1 historical prompt-wording failure** in `tests/promptConstruction.test.mjs:31`. That test expects “Solve the mathematics carefully before writing the response” while the existing prompt says “Solve carefully…”. The temporary broad-run log was lost across the interruption; these counts are retained from the completed run, not a new rerun. Earlier failing/interrupted lint artifacts are superseded by `lint-final.exit` and `lint-final.log`.
